# Place jobs on hosts

Blacksmith runs CI jobs in Firecracker microVMs on a fleet of bare-metal hosts. Every scheduling round, the scheduler takes a batch of admitted jobs and decides which host each one lands on. You will build a miniature version of that placement pass.

Ground rules:

- Use any language you like.
- Model the domain the way you think is right. We care more about how your code is organized than about cleverness; there is no hidden trick.
- Requirements will evolve during the interview. Structure your code so a rule change stays a small change.
- Everything your program needs is in the input file. Never read the wall clock or any other ambient state.

## Input

A JSONL file: one JSON record per line, two record types, in any order.

```json
{"type":"host","id":"h-alpha","total_vcpus":16,"used_vcpus":10}
{"type":"job","id":"j-shark","vcpus":16}
```

- `id`: non-empty string, unique within its record type.
- `total_vcpus` and `vcpus`: positive integers.
- `used_vcpus`: integer, `0 <= used_vcpus <= total_vcpus`.

Definitions used throughout:

- free capacity of a host: `total_vcpus - used_vcpus`
- empty host: `used_vcpus == 0`
- open host: `used_vcpus > 0`

The file is machine-generated by systems outside your control. Decide deliberately what to do with a line that does not match this spec; your program must not crash on one.

## Stage 1: best-fit decreasing

1. Sort jobs by `vcpus` descending. Break ties by `id` ascending (plain ordinal string order).
2. For each job, in that order:
   - Pick the open host with the least free capacity that still fits the job (`free >= vcpus`). Break ties by host `id` ascending.
   - If no open host fits, pick the empty host with the smallest `total_vcpus` that fits. Break ties by host `id` ascending.
   - If nothing fits, the job is unplaced.
3. Charge the chosen host immediately (`used_vcpus += vcpus`) so later jobs see the placement. A previously empty host becomes open.

Largest-first matters: wide jobs must claim scarce empty hosts before narrow jobs fragment them.

## Output

Print exactly one line per job to stdout, in placement order (the sorted order above):

```
<job_id> -> <host_id>
<job_id> -> UNPLACED
```

Anything else you want to print (for example, a note about a skipped input line) goes to stderr. stdout must contain only placement lines.

## Self-check

`fleet.jsonl` is a sample input. `expected-stage1.txt` is the exact stdout a correct stage 1 produces for it.

```
your-program fleet.jsonl | diff expected-stage1.txt -
```
